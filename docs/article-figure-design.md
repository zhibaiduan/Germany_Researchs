# Article Figure Design System

> 本规范定义插入在文章正文中的“图形”：架构图、关系图、框架图、矩阵图、流程图、坐标图、对照图。
> 它不是页面 UI 卡片规范。图形的目标是表达逻辑关系，而不是排列要素。

---

## 1. 定位

文章图形应像研究报告中的手绘结构图：清楚、克制、可读。

核心原则：

1. **关系优先**：先画出因果、层级、递进、约束、输入输出，再放文字。
2. **图形不是 PPT 卡片排版**：卡片可以用，但必须服务于箭头、坐标、层级、边界或流向。
3. **少即是准**：不使用多余装饰线、二层容器、复杂阴影、花哨渐变。
4. **文章一致性**：视觉语言必须贴合 SAP Research 的浅绿纸面、细线、低饱和、报告感。

---

## 2. 图形类型

### 2.1 架构图 / 框架图

用于表达系统结构、上下层关系、支撑层、边界、模块之间的依赖。

常见结构：

```text
上层能力 / 输入 / 上下文
        ↓
核心模块 A → 核心模块 B → 核心模块 C
        ↓
底座 / 约束 / 治理边界
```

规则：

- 上层和底座通常与中间核心模块总宽度对齐。
- 中间模块之间用箭头表达递进，不用纯粹等距排版替代关系。
- 底座不是装饰背景，而是“约束、治理、基础设施、前提条件”。

### 2.2 流程图

用于表达时间、步骤、迁移路径、从左到右的推进。

规则：

- 主流程默认左到右。
- 关键跳转使用实线箭头。
- 可选、依赖、不确定关系使用虚线箭头。
- 每个步骤只保留：标题 + 一句说明。

### 2.3 坐标图 / 矩阵图

用于表达两个维度下的位置判断。

规则：

- 坐标轴要有清晰方向，例如“低 → 高”“浅 → 深”。
- 轴线使用细实线，箭头小。
- 网格线可选，必须低透明度。
- 点位/节点不必追求数学精确，但必须体现相对判断。
- 右上角、左下角等重点区域可用浅色虚线圈或文字标注。

### 2.4 关系网络图

用于表达玩家、资源、依赖、控制权、预算流。

规则：

- 节点大小可以表达权重、控制力、重要性。
- 线条颜色或线型表达关系类型。
- 不要把所有节点排成均匀网格；位置要表达层级和关系。

## 3. 画布

### 3.1 尺寸

正文内图形默认宽度：

```css
width: min(980px, 100%);
```

在当前文章正文约 740px 宽时，图形应完整显示，不需要横向滚动。

推荐逻辑坐标：

| 类型 | 桌面画布比例 | 建议高度 |
|---|---:|---:|
| 简单流程图 | 16:9 到 4:3 | 360-460px |
| 架构图 / 框架图 | 4:3 | 460-560px |
| 矩阵图 | 4:3 或 1.35:1 | 480-620px |
| 复杂关系图 | 1.2:1 到 1.4:1 | 560-720px |

### 3.2 外层

图形只允许一个可见外层容器：

```css
border: 1px solid var(--border);
border-radius: var(--radius);
background: canvas gradient;
```

禁止：

- 外层 figure 一个边框，内部 canvas 又一个完整边框。
- 卡片里再套卡片。
- 使用多个大面积容器造成“网页组件堆叠感”。

### 3.3 画布背景

最大画布可以有轻微渐变，用于营造纸面感：

```css
background:
  radial-gradient(circle at 50% 28%, rgba(255,255,255,.82), transparent 42%),
  linear-gradient(135deg, rgba(255,255,255,.68), rgba(232,238,231,.42));
```

内部几何图形默认不使用渐变，只用简单填充和边框。

---

## 4. 图形标题

图形有两类标题：

### 4.1 Figure Label

文章层面的编号，放在外层上方。

```text
FIGURE 01 · ENTERPRISE AI MARKET MAP
```

样式：

```css
font-size: 11px;
font-weight: 700;
letter-spacing: .1em;
text-transform: uppercase;
color: var(--accent);
```

### 4.2 图内标题

图形自身的中文标题，放在图内右上角。

例如：

```text
企业 AI 应用的 6 个场景
```

样式：

```css
position: absolute;
top: 20px;
right: 24px;
font-size: 13px;
font-weight: 700;
color: var(--accent);
```

规则：

- 图内标题不放在卡片里。
- 不使用过大字号，避免抢正文标题层级。
- 不和 Figure Label 重复同一句话。

---

## 5. 几何图形

允许使用：

- 正方形
- 圆角正方形
- 圆形
- 胶囊形标签
- 细线边界框
- 虚线圈 / 虚线区域

默认节点：

```css
border: 1px solid rgba(24,28,23,.16);
border-radius: 10px;
background: rgba(255,255,255,.72);
```

节点内文字只允许两级：

1. **标题**：`16-18px / 700 / text-1`
2. **备注**：`11-13px / text-2`

禁止：

- 节点内再放 kicker、装饰线、分割线，除非有明确语义。
- 一张节点里放三种以上文字层级。
- 为了“好看”给每个节点加不同视觉效果。

---

## 6. 卡片比例

### 6.1 单行流程卡片

用于 3-5 个并列步骤。

推荐比例：

```text
width : height ≈ 1.2 : 1 到 1.4 : 1
```

正文宽 740px 时，四卡片推荐：

```text
卡片宽：128-140px
卡片高：96-116px
卡片间距：28-36px
```

### 6.2 上层 / 底座卡片

如果中间有 N 张核心卡片：

```text
上层宽度 = 中间 N 张卡片总宽度 + 中间间距总宽度
底座宽度 = 中间 N 张卡片总宽度 + 中间间距总宽度
```

上层和底座要对齐中间模块的左右边界。

---

## 7. 连线与箭头

### 7.1 线型

| 关系 | 线型 |
|---|---|
| 明确流程 / 递进 | 实线箭头 |
| 依赖 / 约束 / 不确定 | 虚线箭头 |
| 背景关联 / 弱关系 | 低透明度细线 |
| 范围 / 重点区域 | 虚线圈或虚线边界 |

### 7.2 箭头

箭头要小，不要像图标一样抢眼。

推荐：

```svg
markerWidth="7"
markerHeight="7"
refX="6"
refY="3.5"
```

线条：

```css
stroke-width: 1.6-2px;
stroke-linecap: round;
opacity: .65-.8;
```

禁止：

- 巨大箭头头部。
- 多条线穿过文字。
- 为每条线加阴影。
- 无语义的装饰连线。

---

## 8. 坐标轴

坐标轴图必须回答两个问题：

1. 横轴表示什么，从哪里到哪里？
2. 纵轴表示什么，从哪里到哪里？

样式：

```css
axis stroke: rgba(24,28,23,.58);
axis stroke-width: 1.5-2px;
grid stroke: rgba(42,96,72,.10-.14);
```

规则：

- 坐标轴标签放在轴末端或轴旁边。
- 网格线不能比节点更显眼。
- 节点不能相互重叠。
- 若节点位置是判断而非数据，应避免伪精确刻度。

---

## 9. 颜色系统

### 9.1 默认颜色

无特殊语义时：

```css
fill: rgba(255,255,255,.72);
stroke: rgba(24,28,23,.16);
text: var(--text-1 / --text-2);
```

默认图形应接近白色或浅灰，不主动上色。

### 9.2 语义色

只有在表达明确语义时才使用颜色。

| 语义 | 色值 | 用途 |
---|---|---|
| 主系统 / 控制 / SAP Research 主线 | `#2A6048` | 主流程、关键判断、默认强调 |
| 数据 / 上下文 / 平台 | `#537791` | 数据智能层、平台层、上下文输入 |
| 业务流程 / 中间协调 | `#8E735B` | 流程协调、过渡、实施链 |
| 风险 / 治理 / 执行边界 | `#A76F63` | 高风险、监管、治理边界 |
| 组织 / 人力 / 支撑域 | `#628458` | HCM、组织智能等辅助域 |

使用比例：

```text
70% 默认白/灰
20% 主线绿色/蓝灰
10% 风险或特殊语义色
```

禁止：

- 每个节点一个颜色。
- 彩虹式分类。
- 内部小节点使用渐变。
- 颜色没有语义，只为装饰。

---

## 10. 图标

可以使用图标，但默认不使用。

使用条件：

- 图标能减少文字，而不是增加装饰。
- 同一张图最多使用一种图标风格。
- 图标尺寸 14-18px。
- 图标颜色跟随节点语义色或 `text-3`。

禁止：

- 图标与文字表达重复。
- 混用线性图标、实心图标、品牌图标。
- 用图标填满空白。

---

## 11. 文案压缩

每个节点最多：

```text
标题：1 行
备注：1-2 行
```

如果节点文字超过 3 行，应重写内容，而不是缩小字体。

推荐格式：

```html
<strong>核心执行</strong>
<span>订单 / 发票 / 库存</span>
<small>直接改变经营状态</small>
```

但视觉上仍应只表现为“标题 + 备注”两级。

---

## 12. 响应式

桌面端：

- 可以使用绝对坐标、SVG 连线、箭头。
- 图形必须完整显示在正文列内。

移动端：

- 优先改成纵向流。
- 隐藏复杂背景连线。
- 保留节点顺序、标题、备注。
- 必要时用简单箭头符号或上下间距表达关系。

禁止移动端横向滚动，除非是大型数据表。

---

## 13. 质量检查

每张图完成后检查：

1. 是否一眼能看出图形在回答什么问题？
2. 是否有明确的主线、箭头或层级？
3. 是否只是把要素排成几张卡片？
4. 是否有多余边框、二层容器或装饰线？
5. 节点文字是否只有标题和备注两级？
6. 箭头是否过大？
7. 颜色是否有语义？
8. 上层 / 底座是否与核心模块对齐？
9. 坐标轴是否标清方向？
10. 移动端是否可读？
